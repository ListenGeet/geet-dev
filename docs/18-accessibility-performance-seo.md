# 18 · Accessibility, performance, SEO

## Accessibility (target: WCAG 2.2 AA)
- **Contrast:** all text at least 4.5:1 (white, `text-2`, yellow-on-black, black-on-yellow pass). `text-3` is only for disabled and decorative items.
- **Focus:** visible 2 px yellow outline with 2 px offset on every control; focus never trapped except inside open sheets and dialogs, which return focus to the opener on close.
- **Targets:** 44×44 px minimum.
- **Keyboard:** everything reachable and operable. Order follows visual order. Shortcuts listed in doc 02 never fire while typing and can be turned off in Settings.
- **Screen readers:**
  - Landmarks: `header`, `nav` (primary), `main`, `aside` (right panel), `footer`.
  - Player: a labelled region "Player"; Play/Pause button toggles its `aria-label` ("Play {title}" / "Pause"); scrubber is `role="slider"` with `aria-valuetext` "1 minute 12 seconds of 3 minutes 51"; the waveform bars are `aria-hidden`.
  - Track row: the row is a list item; the title is a button that plays; the overflow button is labelled "More options for {title}".
  - Live regions: toasts `role="status"`, errors `role="alert"`, chat new messages announced politely, jam member joins announced.
  - Heart: `aria-pressed`.
  - Tabs follow the tabs pattern (arrow keys).
- **Motion:** `prefers-reduced-motion` honoured (doc 01). Nothing flashes.
- **Text size:** respects browser font scaling up to 200 % without loss (use `rem`). Layout reflows at 320 px width.
- **Not color alone:** active tab has a bar and weight; errors have an icon and text; the playing track has the equalizer in addition to yellow.
- **Languages:** `lang` set per page; Punjabi and Hindi text carries `lang="pa"` / `lang="hi"` so screen readers pronounce correctly; content in other scripts marked up where known.
- **Gestures have alternatives:** every swipe action also exists in a menu or button.
- **Audio:** never autoplay on page load. The only automatic sound is the 3.9 s sign-in prompt at preview end, which follows a user-started playback; add a Settings toggle "Play sign-in sound" (default on) for people who find it intrusive.
- Test with VoiceOver (iOS), TalkBack (Android), NVDA (Windows), keyboard only, and 200 % zoom.

## Performance budget (mid-range Android on 4G is the reference device)
| Metric | Budget |
|---|---|
| Largest Contentful Paint (Home) | under 2.5 s |
| Interaction to Next Paint | under 200 ms |
| Cumulative Layout Shift | under 0.1 (reserve cover and banner sizes) |
| JS on first load (Home, gzip) | under 170 KB |
| Time from tap on Play to sound | under 1 s on 4G for a preview, under 1.5 s for full |
| Layout | Server-render Home, Search entry, Artist and Track pages; the player and social areas are client components loaded lazily |

Tactics: preload fonts used above the fold (Outfit 700/800, Inter 400/600 subsets; Gurmukhi and Devanagari load only when needed); covers have fixed width/height and `loading="lazy"` below the fold; `fetchpriority="high"` for the banner image; lazy-load jam, chat, assistant, admin code; keep Realtime connections closed until the user opens chat or a jam; one Realtime socket shared by all subscriptions; avoid layout work during playback (a single `requestAnimationFrame` loop for the scrubber, throttled to 15 fps for bars).

**Data:** covers 600 px JPEGs; audio 128 kbps AAC; previews 0.65 MB. Offer no auto-download on cellular.

**Battery:** pause the waveform animation when the tab is hidden; the audio element keeps playing.

## PWA
- Manifest and `sw.js` provided. Verify installability (Chrome "Install" criteria), shortcuts (Search, Library, Downloads), maskable icon, `theme_color` `#000000`.
- `assets/.well-known/assetlinks.json` is an empty array; when the Android Trusted Web Activity or app is created, fill it with the package name and signing certificate fingerprint.
- Update flow: when a new service worker is waiting, show a small banner "A new version is ready" with **Reload**; never reload automatically during playback.
- Bump the `SHELL` cache version in `sw.js` when the shell file list changes.

## SEO and sharing
- **Indexable:** Home, Artist pages, Track pages `/t/{id}` (with a 40 s preview player and `MusicRecording` structured data), legal pages. **Noindex:** everything else, all dev-domain pages.
- `robots.txt` and `sitemap.xml` (tracks and artists, paginated) generated by the web app. Sitemap is rebuilt daily.
- Titles and descriptions per page type (doc 11). One H1 per page. Canonical URLs on `listengeet.com` (apex), `www` redirects.
- **Open Graph and Twitter cards:** default `og/geet-default.jpg` (1200×630, provided). Track pages use a generated image (doc 04). Playlists are private, so no previews.
- Removed tracks return 410 and drop from the sitemap.
- Structured data: `WebSite` with sitelinks search box on Home; `MusicRecording` on track pages; `MusicGroup` on artists.
- Language alternates are not used (language is a preference, not a URL).

## Security headers (set in both Vercel projects)
`Content-Security-Policy` allowing only self, Clerk, Supabase (https and wss), the storage hosts (B2 endpoint, Supabase storage, optional `cdn.`), and Google fonts not at all (self-hosted); `Strict-Transport-Security`; `X-Content-Type-Options: nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; `Permissions-Policy` disabling camera, microphone, geolocation; `frame-ancestors 'none'`.

## Analytics
None in v1 beyond Vercel's free Web Analytics (cookieless) if desired, and the app's own play counters. No third-party trackers: the privacy page says so, and it makes the GDPR/consent story trivial.
